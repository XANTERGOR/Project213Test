Local Terrain editor reload recovery (2026-10-10)

Scope: code-recompile/domain-reload recovery within the running Unity Editor.
No scene saves, persistent cache assets, package changes or standalone benchmarks.
This is NOT zero-time/zero-flicker reload and does not retain GPU buffers.

Before assembly reload, an already settled editor world can hand off a one-shot
SessionState checkpoint. In-flight geometry/LOD/colliders, pending paint/density,
pending rock seam baking, active drags and unknown/uninitialized worlds are excluded.
Fresh input/density captures must still agree with the last evaluated state.

Recovery checks scene/owner identity, stable source height contents (not managed
array identity), configuration and ordered stamp signatures, generated chunk/LOD/
rock output metadata, and SHA256 of raw vertex/index buffers. Missing or changed
output falls back to the existing rebuild. Transient-only generated rock output is
excluded. A Union cutter using its unchanged original mesh may have no renderAsset
when it does not intersect terrain: this is explicitly proved on both sides of
reload using the same contact algorithm as the build (only that stamp is prepared).
The original mesh must actually be assigned; generated output, stale transitions,
generated material state, and a non-source collider are rejected. Source vertex /
index payload is included in the output hash. Cave cutters, intersecting stamps,
non-cutting trimmed meshes and invalid existing render assets retain strict guards.
Implementation fingerprints are captured when the assembly initializes, NOT after
new source files arrive. Production LocalTerrain C#/shaders/helpers and locked
package files invalidate; *Check.cs and *Tests.cs do not. This is conservative:
an edit in production terrain code may legitimately require a full rebuild.

On a verified handoff the existing meshes remain authoritative. Density baselines
wait for paint recovery; empty transient masks do not by themselves schedule a
second full mesh rebuild. A genuine input/density change still invalidates output.
Manual Apply/Refresh and normal first/opened-world behavior are preserved.

Ready detail cells can cross reload in a separately owned HideAndDontSave
LTDetailPlacementAsset. No serialized component field and no savedPlacement asset
assignment is changed. At most 500,000 resident instances are copied (~22 MB numeric
item payload; object/array overhead is extra). Larger or unfinished populations use
normal generation. The pre-existing exact per-cell input/reference/payload validation
is reused. Stale cells fall through to the user's saved asset or ordinary generation.
GPU resources are released normally; masks, preparation and GPU uploads still occur.
The temporary placement is released on disable; abandoned handoffs are destroyed.

Logs:
  [Terrain Reload] Before [id] -- callback reached, play/hotControl/state counters
  [Terrain Reload] Skip [id] -- exact global/world/unfinished/input/output guard
  [Terrain Reload] Captured ... -- handoff and capture CPU time
    Includes zero checkpoints and skipped count; never silently omits this summary.
  [Terrain Reload] Init: handoff=... -- consumed handoff ID and checkpoint/skip counts
  [Terrain Reload] No checkpoint ... -- once per world/state, normal update path
  [Terrain Reload] ... unchanged geometry restored without rebuild ...
  [Terrain Reload] ... usual update / cold recovery reason

Passive diagnostic menu:
  Tools > Local Terrain > Report Editor Reload Readiness (no scene changes)
Reads existing world/state eligibility and pending counters. It does NOT capture
fresh stamps, call GetState/Detect, rebuild, modify SessionState or save anything.
Readiness is not a promise that fresh input/output verification will succeed.
Diagnostics themselves do not change eligibility. The source-only exception above
is a separate fix to the originally over-restrictive generated-output guard.
