# OpenAI Codex: Unity Art Tools

## Назначение

Этот файл задаёт рабочие правила для Codex при создании инструментов, которые помогают команде импортировать, проверять, организовывать и подготавливать арт для Unity. Он предназначен для Editor tooling и пайплайна ассетов, а не для вызова OpenAI API из собранной игры.

## Контекст проекта

- Unity: использовать версию, указанную в `ProjectSettings/ProjectVersion.txt`; не менять её без отдельной задачи.
- Код инструментов: `Assets/Editor/ArtTools/`.
- Runtime-код, необходимый игре: `Assets/Scripts/Art/`.
- Арт: `Assets/Art/` с подразделами `Textures`, `Materials`, `Models`, `Animations`, `VFX`, `UI`, `Audio`.
- Настройки инструментария: `Assets/Art/Editor/ArtToolsSettings.asset`.
- Все изменения должны быть совместимы с Git и не генерировать файлы в `Library/` или `Temp/`.

## Правила для Codex

1. Перед изменением файлов изучить существующие `.asmdef`, импортёры, `AssetPostprocessor`, настройки Addressables и соглашения по именованию.
2. Предпочитать маленькие EditorWindow, `ScriptableObject` и отдельные сервисы вместо одного глобального менеджера.
3. Не менять импорт ассетов глобально без явной настройки и режима Preview/Apply.
4. Любая массовая операция должна поддерживать фильтр по папке/типу, отчёт об изменениях и отмену через `Undo` там, где это возможно.
5. Не хранить секреты, токены или API-ключи в Unity-проекте, ScriptableObject, `Resources` или исходниках.
6. После изменений проверять компиляцию Unity Editor и отсутствие ошибок в Console; для Editor-кода добавлять тесты только там, где они проверяют нетривиальную логику.

## Базовые возможности инструментария

### Импорт и валидация

- Проверять формат, размер, цветовое пространство, alpha, mipmaps, compression и максимальное разрешение текстур.
- Проверять модели: scale, normals, tangents, animation import, material extraction и наличие запрещённых компонентов.
- Проверять имена по шаблону: `ประเภท_Name_Variant_Resolution`, например `T_Environment_Rock_A_2K`.
- Показывать ошибки и предупреждения в отдельном отчёте с путём к ассету.
- Применять настройки через явную команду `Apply`, не во время каждого domain reload.

### Организация и Addressables

- Использовать стабильные адреса и группы Addressables по назначению (`Art_Environment`, `Art_Characters`, `Art_UI` и т. п.).
- Не переименовывать адреса без миграционного плана.
- Предоставить команды для поиска дубликатов, неиспользуемых ассетов и отсутствующих ссылок.
- Не редактировать `.meta` вручную и не удалять их отдельно от исходного ассета.

### Превью и пакетные операции

- Создать EditorWindow с выбором папки, фильтрами, Preview, Apply и экспортом отчёта в JSON/CSV.
- Для длительных операций использовать `EditorUtility.DisplayProgressBar` или современный progress API и корректно очищать progress при исключении.
- Пакетные операции должны быть детерминированными и повторяемыми.

## OpenAI-интеграция

Если инструмент использует OpenAI для описаний, тегирования или поиска по арт-библиотеке, запросы должны идти через контролируемый серверный прокси. Unity Editor обращается к прокси по HTTPS; ключ хранится только в переменных окружения или секрет-хранилище CI.

- Не встраивать ключ в C# и не коммитить `.env`.
- Ограничивать размер и тип отправляемых изображений.
- Явно получать согласие на отправку приватного или лицензированного арта.
- Сохранять результат как проверяемые метаданные, а не автоматически перезаписывать исходные ассеты.
- Модель, endpoint и формат ответа задавать конфигурацией прокси; не использовать устаревшие `davinci-codex` или `/v1/engines/...`.

## Производительность и безопасность

- Не сканировать весь `Assets/` на каждый `OnPostprocessAllAssets`; использовать очередь и кэш хэшей.
- Не выполнять тяжёлые операции на главном потоке без progress и возможности отмены.
- Не загружать большие изображения в память без ограничения размера.
- Все пути нормализовать и ограничивать корнем проекта.
- В отчётах не сохранять секреты и содержимое приватных исходников.

## Definition of Done

- Инструмент открывается из меню `Tools/Art Tools`.
- Preview показывает точный список изменений, Apply меняет только выбранные ассеты.
- Повторный запуск не создаёт лишних изменений.
- Ошибки импорта и валидации видны с кликабельным путём к ассету.
- Проект компилируется без ошибок, а изменения не затрагивают `Library/`, `Temp/` и пользовательские секреты.
