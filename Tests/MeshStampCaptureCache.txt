Mesh-stamp editor capture cache (2026-10-10)

Scope: editor-only geometry capture in LTEditorEngine.Tick. No vegetation settings,
rendering paths, shaders, scene assets, package versions or quality settings changed.
No standalone performance, streaming or memory checks were resumed.

Each LTWorld state retains at most one geometry snapshot per encountered mesh stamp.
The key includes source identity, dirty revision, vertex/index/submesh counts, exact
mesh-to-world matrix and the existing asset dependency hash. Settings are captured
fresh into a NEW Stamp every poll: blend/cut/LOD edits must not be hidden by a geometry
cache hit. Build-specific contact segments and cut rows are never shared.

Unchanged hits skip reading source arrays, transforming/welding vertices and extracting
contact faces/edges. A content audit every >=1 second of polling compares vertices and
all submesh indices using reusable buffers. It detects same-count geometry writes that
did not mark the source dirty. Such unannounced changes may take up to the next audit
plus editor scheduling to appear. Exact source content is folded into the stamp signature
so an audit-detected change also dirties output, rather than only replacing the cache.

Undo clears the cache. Reimports use asset dependency changes. Manual Apply/Refresh,
scene-save flushing and full rebuild all capture afresh. Disabled/removed stamps are
pruned after capture; disabled worlds, play entry and assembly shutdown clear entries.
Read-only preview captures bypass the cache. Unreadable sources cannot use stale hits.
The retained array payload budget is 64 MiB per world; oversized/full-cache inputs still
work uncached. This is not a total-memory limit: working builds, entry overhead and shared
audit scratch buffers are additional. Old snapshots remain valid for in-flight builds.
