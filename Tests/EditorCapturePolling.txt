Editor Capture polling optimization (2026-10-10)

Scope
- LT.Editor.Capture previously reached 2.057 ms total in the partial CPU-only
  flight-20261009-234925-342-ca6fef9d capture. This is the baseline, not a result
  of this change. Frame maximum was 14.871 ms with coincident LOD/Capture work.
- LTRoadTerrainLODCapture still queries the live generated hierarchy every poll,
  checking owner, activation, bake validity, mesh identities/readability, dirty
  counts, dependency hashes, vertex/submesh counts, matrices, order and settings.
  It reuses scratch lists and the exact old road-foundation-v2 string when those
  inputs are unchanged, instead of reformatting every matrix/mesh into text.
- LTRoadCaptureSignature compares matrix float bits, not approximate equality
  or a collision-prone hash. Changes of number-format symbols also invalidate
  text reuse. A failed/abandoned input collection does not commit a new key.
- The immutable surface cache's validity rules and conservative null/fallback
  outputs are unchanged. Scratch Unity object references are cleared in finally.
  This does NOT introduce new detection guarantees for an unmarked native mesh
  content edit which changes neither dirty count nor existing metadata/hash.
- LTRoadJunction.SourceMember uses live TryGetComponent for optional boundary
  components; there is no negative-result cache. Generated/nested boundaries,
  root acceptance, inactive/disabled components and ordering are preserved.
- Coarse markers now separate Capture.Road, Capture.RoadFoundation,
  Capture.Junction, Capture.Height and Capture.Mesh. RoadFoundation is nested
  under Road, so do not add parent/child inclusive durations together.
- No polling intervals, build budgets, terrain geometry, scene/settings/assets,
  vegetation placement or reload ownership rules were changed.
