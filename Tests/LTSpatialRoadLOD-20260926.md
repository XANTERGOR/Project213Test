# Module asphalt and within-chunk terrain LOD

## Use

Road -> Asphalt -> «Меш асфальта»:

- «Источник меша» = ProceduralRibbon keeps the existing generated ribbon. Offroad is unchanged.
- Module accepts a Mesh or a prefab asset (prefab takes precedence). MeshRenderer/MeshFilter only; no source edits or scene-object duplication. Prefab root scale is ignored; child transforms are applied. Negative child scale is rejected.
- Choose the longitudinal X/Z axis. Y is up; moduleBaseY is the authored road-surface height, normally zero. Width can fit the road width; repeat length 0 uses the original length. An integer number of repeats is fitted uniformly to the path, so there is no cut tail.
- A repeatable module needs matching cross-sections at both ends, readable vertices, normals, tangents and UV0, and enough longitudinal subdivisions to bend. UV0–UV3, colors and material submeshes are retained. Higher UV channels, blendshapes and skinned meshes are not supported.
- Prefab materials are used unless «Материал асфальта» overrides them. A direct Mesh uses «Материалы модуля» by submesh, or the same override.
- Automatic LOD targets 50/25/12.5% triangles, subject to a source-plane error tolerance and locked open/material/UV/end boundaries. It is conservative; reduction is not guaranteed for already minimal or fully split meshes. Limit: 20,000 source vertices for the simplifier. Topology uses endpoint edge collapse, link-condition and normal-inversion checks, not QEM or a Hausdorff-distance guarantee.
- Authored uses a prefab LODGroup or the separate LOD1–LOD3 Mesh fields. All end contours must match LOD0. The generated ribbon always uses sampled-row reduction. Its Simplification Steps / error entries are not used; its LOD row stride doubles by level.
- Start Distance controls each section's LOD, with LTWorld camera/preview/force/hysteresis controls. Colliders always reference LOD0. Triangle totals are reported below the road inspector.
- Source-module LOD preparation is cached (at most 8 road entries); moving a spline point only bends the prepared levels. Generated output is saved as content-addressed meshes under the existing owned `Assets/LocalTerrainRoads/<id>` directory. Older output remains for Undo/reuse.

LTWorld -> «Геометрия»:

1. Enable LODs, choose «Режим LOD» = WithinChunk.
2. «Участков по стороне» = 4 gives 4x4 independent patches per chunk (values round up to 1/2/4/8).
3. Existing LOD distances, height errors and simplification steps apply. Enable Preview LODs to use the Scene camera; Play uses lodCamera or Camera.main.
4. Auto Update rebuilds bake data after settings change; otherwise use the existing rebuild button.

The old WholeChunk path remains the default for existing scenes and retains its legacy fixed borders. WithinChunk now uses adaptive, globally balanced (2:1) cell edges, including across chunk boundaries. There are no permanently fine patch-border strips. This is patch-based distance selection, not Unity Terrain's implementation or GPU continuous tessellation. Hard LOD changes may still pop; no geomorph/crossfade is implemented. Protected road and rock-contact cells retain their detail and original stitch masks. Smaller patches give finer distance-selection granularity and more metadata.

One MeshRenderer and material binding remains per chunk. An owned runtime clone of a persisted vertex bank receives a combined index list when local topology or neighbouring edge stitches change (10 Hz selection). A shared coordinator resets changed patches and the dependency closure of previously forced refinements, then balances neighbouring cells. Moving away can therefore remove refinement again. No heights, masks, painting, vegetation or colliders are regenerated by camera movement. Extra baked index variants, hierarchy storage and index-upload CPU cost are the tradeoff, not a guaranteed FPS gain. Variants are baked only for cells reachable from requested levels; search-only ancestors have no index payload.

Vertex banks, cell hierarchies and stitch variants are stored beside chunk assets as `_SpatialLOD.asset` (mesh subasset), format version 2. Existing v1 data requires one geometry rebuild using Auto Update or **Rebuild All + Save Meshes**. Until every chunk has compatible data, the world falls back to LOD0 and displays a warning in the inspector; old and new seams are never mixed. Legacy extra LOD assets are not deleted. Runtime clones are never persisted and are released on disable, reload and scene saving. An unchanged selection still refills a recreated preview clone. Source terrain/meshes and user scenes are not saved by the implementation check.

Diagnostics shows the actual assigned triangle count for spatial LOD across all chunks (before camera culling), rather than zeros for the unused legacy LOD mesh arrays. It is not a GPU hardware counter.

## Verification

- Managed production planner/emitter: 8 multi-chunk layouts with 1x1 / 2x2 / 4x4 / 8x8 patches, five levels (LOD0–4), curved heightfield, varying base densities and protected holes crossing chunk edges. LOD0 matches production geometry; mixed levels retain identical interior boundary contours (no open patch/chunk cracks).
- 224 mixed/incremental selections compared with fresh global balancing; returning far removes forced refinement. Uniform far surfaces have exactly the expected coarse triangle count, with no dense border grid. A 16x16-chunk synthetic topology verifies local reset/upload scope and return-far cleanup. Warm idle topology updates allocate 0 bytes and do no topology work; this does not assert zero allocation for all Unity rendering.
- Managed module preparation: three automatic ratios, deterministic results, preserved border vertices, manifold edge incidence, positive winding, curved/banked repeated modules, matching end geometry/normals, UV/color preservation and unchanged source hash.
- Full pre-existing managed regression suite passes alongside these tests.
- C# editor project build passed after the adaptive-stitch change (0 errors, 6 warnings). These tests do not instantiate Unity native Mesh objects, import the user's prefab, render the scene, or measure live-scene performance. Native import/render/save/reload behavior still needs a Unity check.

No standalone vegetation benchmark, quality presets, package modifications, cleanup, scene save or Unity restart was performed.
