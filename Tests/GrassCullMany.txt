Shared grass GPU visibility calculation - 2026-10-10

Change and control:
- LTDetailRenderer exposes "Объединять GPU-отсечение" (gpuUnifiedCulling),
  default true. It applies when the existing GPU details path is enabled.
  Turning it off restores the single-output compute path without rebuilding
  placement. The inspector shows total / unified cull dispatches.
- CullMany computes distance, existing density thinning, LOD and frustum once
  per instance per packet, then routes instance IDs to up to eight existing
  append lists. The Windows D3D11/12 backend retains the same indirect draws.
- Single-list groups and single-list packet tails use the original Cull kernel.
  Unsupported CullMany kernels and optional padding allocation failures use
  the original path. More than eight lists are processed in multiple packets.
- Draw order, meshes, materials, instance sets, existing LOD thresholds,
  distances, density, shadow rules and raster shaders are preserved. In
  particular, offscreen shadow casters are retained as before.
- Each unused output slot binds a distinct, never-written one-uint append
  buffer. The shared pool is accounted for and freed with the existing buffers.
  It does not duplicate the full instance data. No production GPU readbacks.

Why this is optional:
The previously saved Scene View profile is CPU submission evidence, not a new
FPS measurement: Logs/FrameProfiles/flight-20261010-162202-816-ad7ee47e-markers.csv.
It contains about 346 cull dispatches for 337 TryRender calls per frame. Many
groups therefore offer little opportunity for combining selections. The main
benefit is expected for prefabs with several active LOD/shadow lists. This
change does not establish a measured speedup for the user's current scene.
