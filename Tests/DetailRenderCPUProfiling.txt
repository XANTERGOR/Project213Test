Material adaptation optimization (2026-10-10)
--------------------------------------------
LTDetailGpuRenderer now retains the adapted handle in its per-Begin dictionary.
Warm prepared-camera hits perform one dictionary lookup without repeating the
persistent-material lookup, native clock read or last-use dictionary write.
Direct/unprepared calls preserve per-draw last-use touches. Begin and Dispose
clear the handle cache; expiration still destroys only renderer-owned materials.
An entry is published only after successful synchronization, allowing copy errors
to retry without leaving a falsely initialized adapter.

Full CopyPropertiesFromMaterial is STILL performed on first use in every Begin,
including unchanged materials. No cross-frame dirty/CRC-based cache was added.
Thus arbitrary script/animation/Inspector edits remain visible on the next pass,
without requiring SetDirty or change notifications. Shader replacement is checked.
After the copy, the actual target instancing/pass flags are read; setters execute
only when a value differs. This deliberately does not assume whether native Unity
property copying also copies those flags. Source materials are never changed.

Three new CPU scopes, in addition to the original 12:
  MaterialAdapt -> MaterialSync -> MaterialCopy / MaterialPasses
MaterialAdapt includes cache hits; MaterialSync is actual first-use sync; Copy
isolates the full property copy and Passes isolates flag comparisons/writes.
All are CPU-only, nested, and included automatically by the existing report.
No culling/LOD, density, shadows, draw order, settings, shaders or GPU data changed.

Implemented a separate explicit live mode on LTDetailRenderer:
- "Кэш материалов по уведомлениям" (gpuMaterialNotifications), default FALSE.
- "Материалы с уведомлениями" (gpuNotifiedMaterials), default empty allowlist.
  Both opt-in and a listed source are required; prefabs are never auto-enrolled.
  No serialized scene/prefab/material is changed or saved to enable it.
- Unlisted/default sources retain full property copying once per camera pass.
  Listed materials reuse a receipt across passes only while notification revision,
  global invalidation epoch and source/adapter/target shader guards match.
  Synchronous same-pass hits retain the cheap path; writes must notify before
  another consumer renders. The first use in each pass checks shader identities.
- LTDetailMaterialNotifications.NotifyChanged(material) after a completed write;
  prefer Mutate(material, m => { ... }) when a write may throw/re-enter rendering.
  Mutate invalidates before/after and prevents receipt publication during a write.
  NotifyChanged is the low-overhead completed-write path; Mutate uses a temporary
  registration and callers may also allocate a delegate. No zero-GC claim.
- Registration is per consumer with shared ref-counted source state. Disabling,
  list changes and Dispose release registrations; final release drops static
  references. Target expiration clears receipts. Failed sync never publishes one.
- Before each Editor camera pass, registered materials' and shaders' dirty counts
  are checked (NOT property enumeration or CRC). Undo/Redo, play-mode transitions,
  assembly reload and asset imports invalidate; imports also reload the adapter map.
  These signals do NOT detect arbitrary unnotified third-party runtime Set* calls.
  Such materials must remain OUT of the allowlist. A negative control tests this.
- Inspector counters are successful full copies / reuse calls in the last camera
  pass, not frame time or independent materials saved. Reuse includes same-pass hits.
